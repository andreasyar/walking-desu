# Walking Desu — wand6 / 4.x

Текущий стабильный выпуск: **[4.2.1](https://github.com/andreasyar/walking-desu/releases/tag/v4.2.1)**
([инструкция](docs/RELEASE-4.2.1.md)). Основная ветка `master` — завершённая
линия wand6 (этапы восстановления 7–14 плюс патч плавности клиента), от
исторического снимка `b9d8a8043b0d2f19f42770f4f3a7eceb849c8bfa`.

В игре: независимая сборка, карта/движение, мультиплеер, PvP, tower defence,
предметы и инвентарь. В **4.2.1** убрано периодическое дёрганье движения на
Linux/Wayland (`paintImmediately` + `Toolkit.sync()`, цель ~60 fps) —
см. [CLIENT-SMOOTHNESS.md](docs/CLIENT-SMOOTHNESS.md).

Стабильная **3.2.0** сохранена в ветке `codex/game-3.x` и в
[релизе v3.2.0](https://github.com/andreasyar/walking-desu/releases/tag/v3.2.0).
Клиентские дистрибутивы **не содержат спрайтов**: положите локальный `assets/`
по [CLIENT-ASSETS.md](docs/CLIENT-ASSETS.md), как для 3.2.

## Сборка

Нужен JDK 21 (для сборки используем Dev Container) и Gradle Wrapper 9.8.2:

```sh
./gradlew clean build :client:guiCheckAgent
```

Внешние библиотеки, старые `classes/` и сборка 3.x не требуются.
`build` проверяет публичную упаковку, многопользовательскую видимость/доставку/
очистку соединений и выполняет сетевой smoke-тест
на отдельном сервере с автоматически назначенным портом, а также проверки
движения, генерации карты, серверного боя, башен, волн, сброса мини-игры,
инвентаря и атомарного подбора предметов. Изображения для
сборки не нужны. Современные source set включают только:

- `common/src/main/java` — модель и обе стороны сериализованного протокола;
- `client/src/main/java` — графический клиент;
- `server/src/main/java` — сервер без GUI-зависимостей.

Проверочные классы лежат в отдельных `src/checks/java` и не входят
в дистрибутивы. Контракт сообщений несовместим с 3.x: клиент и сервер
нужно брать из одного комплекта wand6. Сообщения этапа 12 расширяют протокол
этапов 7–11: обновляйте обе стороны вместе. Исторические Ant/NetBeans-скрипты
и старое дерево `src/` убраны из актуальной линии — их можно смотреть
в старых релизных коммитах и в ветке `codex/game-3.x`.

### Канонические пути сборки

| Назначение | Путь |
| --- | --- |
| Thin JAR модулей | `{common,client,server}/build/libs/{common,client,server}-4.2.1.jar` |
| Standalone сервер | `server/build/libs/wand6-server-4.2.1-standalone.jar` |
| Runnable install (скрипты в `bin/`) | `{client,server}/build/install/wand6-{client,server}/` |
| Релизные ZIP/TAR | `{client,server}/build/distributions/wand6-{client,server}-4.2.1.{zip,tar}` |
| Dev-клиент с картинками | `.devcontainer/artifacts/wand6-client/` ← `:client:publishDev` |
| Dev-сервер для Compose | `.devcontainer/artifacts/wand6-server/` ← `:server:publishDev` |
| GUI agent JARs | `client/build/libs/client-4.2.1-*-gui-check-agent.jar` |

Картинки для клиента: вход `.devcontainer/assets/wand6/` (или `-PclientAssetsDir`);
в публичные архивы не входят. Каталоги `.devcontainer/artifacts/client/` и
`server/` — **legacy 3.x**, wand6 их не обновляет; см.
[.devcontainer/artifacts/README.md](.devcontainer/artifacts/README.md).

## Запуск дистрибутивов

Распакуйте ZIP или TAR из `client/build/distributions/` и
`server/build/distributions/`. Предоставьте атлас `summer.png` и кадры peasant, poring, tower, canon и `coin_stacks_gold.png` по инструкции
[CLIENT-ASSETS.md](docs/CLIENT-ASSETS.md). Дистрибутивы изображений не содержат.

```sh
/path/to/wand6-server-4.2.1/bin/wand6-server 45001
/path/to/wand6-client-4.2.1/bin/wand6-client localhost 45001
```

Windows: соответствующие `.bat`. По умолчанию используется порт 45000;
для совместного запуска с 3.x указывайте другой свободный порт. Значение `0`
у сервера выбирает свободный порт и печатает `WAND6_SERVER_PORT=<port>`.
Текст отправляется через поле ввода и Send (или Enter), до 100 символов.
Игроки видят друг друга в радиусе 500 пикселей; учёт видимости обновляется
каждые 50 мс. Последний текст возвращается при повторном появлении игрока.
После отключения закройте окно и запустите клиент снова: новый вход создаёт
нового персонажа в начальной точке, автоматического reconnect нет.

Также доступен `java -jar server/build/libs/wand6-server-4.2.1-standalone.jar 45001`.
Управление: ЛКМ — движение к точке, ПКМ — остановка. Сервер задаёт скорость
70 пикселей/секунду; вода (высота ≤50) и горы (высота ≥200) непроходимы.
Движение прямое: у препятствия персонаж останавливается, обход не строится.
Команда дальше 4096 пикселей или за границу мира останавливает движение.
ЛКМ по другому игроку, монстру или башне выбирает цель, F3 отправляет одну атаку; Esc/Shift снимает
выбор. Сервер проверяет цель, дальность ≤500 пикселей и интервал ≥375 мс.
У каждого 100 HP, удар наносит 50; выстрел задержан на 375 мс, затем летит
со скоростью 1000 пикселей/с к исходной точке цели. Движение цели не отменяет
попадание; смерть/отключение любого участника отменяет его снаряды.
После смерти сервер сразу восстанавливает HP и переносит игрока в (512,512),
а клиент проигрывает 450 мс анимации тела на месте гибели. Всё золото выпадает
в точке смерти; при отключении — в последней серверной позиции.

Монстр при гибели оставляет 1–99 монет со смещением ±10 по каждой оси.
ЛКМ по монетам подводит персонажа и отправляет запрос подбора. Сервер
проверяет дальность ≤50 пикселей; один предмет достаётся одному игроку.
Золото объединяется в стек с сохранением ID; количество видно справа вверху.
ПКМ, Esc, новое движение или строительство отменяют ожидание подбора.
Если прямой путь перекрыт, обойдите препятствие и нажмите на монеты снова.
Инвентарь не сохраняется между подключениями; выпавшее золото можно подобрать повторно.

Строительство: **B**, затем ЛКМ по месту; Esc отменяет выбор места.
Башня бесплатна, как в стабильной 3.2. Сервер разрешает строительство
на проходимой клетке в пределах 500 пикселей от игрока, не ближе 32 пикселей
к другой башне, не чаще раза в секунду; одновременно допускается до 128 башен.
Башня имеет 1 HP и может быть уничтожена игроком; она автоматически выбирает
первого подходящего монстра в радиусе 200 и наносит 10 урона раз в секунду.
Её снаряд летит 1000 пикселей/с без задержки анимации выстрела.

Первая волна приходит через 20 секунд после запуска сервера: 5 poring с 20 HP,
скоростью 70 или 80 пикселей/с, из области x=544…830, y=0…63 к (705,755).
Каждые 20 секунд приходит следующая. Если пропусков не было, сила растёт на 1,
количество — на 5; здоровье равно 20 × сила. Монстры идут прямым маршрутом,
как в 3.2; проверка воды/гор применяется к игрокам и строительству.
При 100 пропусках на следующей границе волны сервер удаляет все башни,
старых монстров и их снаряды и начинает новый цикл с пяти монстров.
Счётчик волны, пропусков и силы виден в окне; игроки, их инвентарь и
уже выпавшие предметы при сбросе сохраняются.

В углу окна клиент показывает `fps`, максимальный интервал кадра (`max`) и
последнее расхождение `TIMESYNC` (`sync`). Ожидайте около **60 fps**.

Клиент требует настоящую графическую сессию и предлагает выбрать ник длиной
3–10 символов. Выход — закрытие окна. Сервер останавливается Ctrl+C.

Для запуска через Gradle:

```sh
./gradlew :server:run --args='45001'
./gradlew :client:run --args='localhost 45001'
```

По умолчанию локальный атлас находится в `.devcontainer/assets/wand6/img/`.
Другой каталог: `-PclientAssetsDir=/absolute/path/to/assets`.
Локальный прогон:

```sh
./gradlew :client:publishDev :server:publishDev
.devcontainer/artifacts/wand6-client/bin/wand6-client localhost 45000
# Compose-профиль runtime монтирует artifacts/wand6-server/
```

## Проверки и ограничения

Для автоматизированной проверки настоящего GUI **на хосте** с графической Java:

```sh
python3 tools/check-wand6-distributions.py --assets .devcontainer/assets/wand6
```

Сначала выполните сборку с `:client:guiCheckAgent`. Скрипт распаковывает свежие
дистрибутивы, проверяет архивы и диагностику ошибок, запускает production-скрипты
сервера и клиента, проходит вход, плавное движение, остановку, восемь
направлений, переход фрагмента, resize/клики и остановку перед горой. Check-only Java
agent снимает живое Swing-окно на EDT. Логи и PNG лежат в отдельном каталоге
`client/build/distribution-check/run-*/`; скрипт завершает только свои процессы.
PNG нужно просмотреть; это не захват рабочего стола. Ресурсы и снимки остаются локально.

Для автоматизированной проверки двух настоящих клиентов, текста, выхода из
области видимости и повторного входа:

```sh
./gradlew :client:multiplayerGuiCheckAgent
python3 tools/check-wand6-multiplayer.py --assets .devcontainer/assets/wand6
# Обратный порядок входа именованных клиентов:
python3 tools/check-wand6-multiplayer.py --assets .devcontainer/assets/wand6 --first two
```

Скрипт распаковывает свежие TAR, запускает отдельный сервер на порту `0`,
два production клиента в отдельных JVM и повторный клиент после выхода.
Логи и девять PNG живых Swing-окон — в `client/build/multiplayer-gui/run-*/`.
Снимки нужно просмотреть. Точная граница 500/501, адресаты и RST проверяются
также отдельной задачей `:server:multiplayerCheck`, входящей в `build`.

Для автоматизированной проверки PvP двумя production-клиентами:

```sh
./gradlew :client:combatGuiCheckAgent
python3 tools/check-wand6-combat.py --assets .devcontainer/assets/wand6
```

Скрипт распаковывает свежие дистрибутивы и запускает изолированный сервер на
порту `0`. Проверяет выбор цели/F3, снаряды, здоровье, смерть/возрождение и
ответную атаку. Восемь PNG живых окон и логи — в
`client/build/combat-gui/run-*/`; снимки нужно просмотреть. Сетевые гонки,
недопустимые атаки, позднее появление и отмену при EOF/RST проверяет
`:server:combatCheck`, входящая в `build`.

Для автоматизированной проверки tower defence двумя production-клиентами:

```sh
./gradlew :client:towerDefenceGuiCheckAgent
python3 tools/check-wand6-tower-defence.py --assets .devcontainer/assets/wand6 --first two
```

Скрипт проверяет B/клик, естественные первую и вторую волны, движение poring,
снаряды/попадания/смерть, пропуски, уничтожение башни через ЛКМ/F3 и повторное
строительство. Логи и 14 PNG живых окон — в `client/build/tower-defence-gui/run-*/`.
Сброс при 100 пропусках, усиление, гонки попаданий, отмена и согласованность
сетевых клиентов проверяются в `:server:towerDefenceCheck`, входящей в `build`.
Полный сброс не заявляется проверенным по снимку одной волны.

Для автоматизированной предметной проверки двумя production-клиентами:

```sh
./gradlew :client:itemGuiCheckAgent :server:compileChecksJava :client:distTar :server:distTar
python3 tools/check-wand6-items.py --assets .devcontainer/assets/wand6
```

Check-only серверная фикстура задаёт две стопки (7 и 5) и одного poring;
дальше используются обычные клиентские ЛКМ/F3/B, модель и сетевой протокол.
Проверяются подход/подбор/объединение, счётчик и resize, PvP со смертью и
выпадением/повторным подбором, награда за убийство башней, выход владельца
и подбор его золота оставшимся игроком. Логи и 14 PNG — в
`client/build/item-gui/run-*/`; снимки нужно просмотреть.
Гонки двух игроков и отключения, переполнение и граница видимости проверяются
`:server:itemCheck`; модель — `:common:inventoryCheck`; сохранение предметов
при полном сбросе — `:server:towerDefenceCheck`. Все входят в `check`/`build`.
Выбор необходимых GUI-прогонов по затронутому коду описан в
[отчёте этапа 12](docs/RECOVERY-STAGE-12.md).

Работают независимая сборка, вход с серверными координатами и временем,
детерминированная карта, движение/анимации из 3.2, взаимная видимость,
текст, PvP/здоровье/смерть/возрождение и закрытие соединений без завершения всего сервера. Камера ограничена
миром; отрисовка и клики используют один снимок камеры. Отладочную сетку можно
включить JVM-свойством `-Dwand6.debugMap=true`.

С локальными изображениями отдельно выполните `./gradlew :client:visualCheck`.
Протоколы 3.x и 4.x несовместимы. Клиент и сервер 4.2.0/4.2.1 совместимы по
сети; для исправления дёрганья нужен **клиент 4.2.1**. Релиз:
[v4.2.1](https://github.com/andreasyar/walking-desu/releases/tag/v4.2.1)
([инструкция](docs/RELEASE-4.2.1.md), базовый [4.2.0](docs/RELEASE-4.2.0.md)).
Откат на 3.2 — [v3.2.0](https://github.com/andreasyar/walking-desu/releases/tag/v3.2.0)
и ветка `codex/game-3.x`. Сервер не предназначен для публичного размещения.
Проверки Windows/macOS не проводились.
