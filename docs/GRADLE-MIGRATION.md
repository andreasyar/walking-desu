# Переход на Gradle

Дата: 2026-11-01.

## Выбор игровой линии

Критерий пользователя — полнота игрового клиента и сервера, а не новизна
каталога. Текущий до миграции `wand6` — незавершённая переработка:
`CurveMovement` содержит заглушки, клиент ссылается на классы старого клиента,
а старый клиент уже потерял свою точку входа. Старые сборочные скрипты и
настройки NetBeans выбирали разные поколения приложения.

Для новой сборки восстановлены Java-исходники из согласованного состояния
`240235e801d318d86d05bbd6ebf50d2301b5a2ab` (этап 3.1.0).
Оно содержит клиент `WalkingDesu`, сервер `JavaTestServer`, подсистемы PvP,
башен, монстров, подбора предметов и инвентаря. Эта полнота определена по
коду; все игровые сценарии не объявляются проверенными.

Перед выбором все Java-исходники кандидатов компилировались в dev-контейнере
на Java 21:

| Состояние | Результат |
| --- | --- |
| `d2cfc06` — Pickup. Inventory | Компилируется, более ранний вариант модели предметов |
| `240235e` — переработка предметов | Компилируется, сохранены игровые подсистемы |
| `6425041` — непосредственно перед wand6 | Не компилируется: 112 ошибок |

Промежуточные коммиты после `240235e` начали переработку отрисовки и общей
модели; их новизна не означает большей функциональной готовности.
Выбор не является доказательством, что это последняя работоспособная версия
во всей истории. `wand6`, C++/Scheme-эксперименты и прочие исторические
исходники доступны в Git, но в новую сборку не включены.

## Структура

95 Java-файлов перенесены в стандартные Gradle-каталоги `src/main/java`
трёх модулей. Пакеты сохранены, кроме `server.javatestserver.MapFragment`:
эта модель использовалась и клиентом, и сервером, поэтому перенесена в
`common.MapFragment`, а импорты обновлены. Серверные реализации не входят
в клиентский classpath, клиентские — в серверный.

Скрипты shell/PowerShell, Ant/NetBeans, Visual Studio-проекты, ручные
манифесты и JNLP удалены. Их обязанности выполняют Java/Application-плагины
Gradle, Wrapper и задачи публикации dev-артефактов.

Wrapper 9.8.2 получен из официального Git-репозитория Gradle, его JAR
проверен по официальному SHA-256:
`3b8a25775a69158b5ad2b1d17a80a88dc7b40a352a73eb27d06c612a7ce68e98`.
Контрольная сумма дистрибутива также зафиксирована в Wrapper properties.

Графика остаётся локальной и передаётся через `clientAssetsDir`.
`client/required-assets.txt` перечисляет 280 путей из восстановленного
профиля выбранного состояния. Проверка наличия ресурсов не заменяет
визуальную проверку игры. Происхождение и неоднозначные варианты описаны
в корневом README и историческом аудите.

## Проверено после миграции

- `./gradlew clean build prepareDev` в работающем dev-контейнере:
  полная сборка, ZIP/TAR-дистрибутивы и публикация dev-артефактов.
- Повторная принудительная сборка клиентского JAR и standalone-сервера:
  SHA-256 совпадают с предыдущими результатами.
- Упаковка клиента без каталога графики отклоняется с перечнем отсутствующих
  ресурсов; все 280 изображений из собранного клиентского JAR читаются ImageIO.
- Проверено отсутствие серверных классов в клиентском JAR и клиентских
  классов/графики в standalone-сервере. Общая библиотека не содержит
  клиентских или серверных реализаций.
- Серверный контейнер собран и запущен с новым артефактом; отдельный Java-клиент
  проверки выполнил вход, получил сгенерированный фрагмент карты и ответ
  на движение через реальный протокол сериализованных сообщений.
- Результаты сборки принадлежат UID/GID пользователя хоста (`1000:1000`).

Эти проверки сборки и протокола выполнялись отдельно; автоматизированных
тестов игровых функций в исходном прототипе нет. Графическое окно клиента,
PvP, башни и инвентарь вручную после миграции не проверялись.
Предупреждения Java о deprecated API и unchecked cast остались в историческом
коде. Предупреждений о deprecated Gradle API в новой конфигурации нет.
