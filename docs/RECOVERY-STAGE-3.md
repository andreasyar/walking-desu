## Реализация решений

| Решение | Реализация и результат |
| --- | --- |
| R01 | `DirectionalSpriteSet` сохраняет пути и индивидуальные наборы. EAST/WEST у desu и tower явно используют SOUTH_EAST/SOUTH_WEST. Проверяются все восемь направлений; пустое направление и неизвестный набор дают `IllegalArgumentException` с именем, загрузчик не вызывает `System.exit`. Кэш загрузки синхронизирован. |
| R02 | `UnitPainter` получает текущий Graphics и FontMetrics при paint, формирует имя над спрайтом с сохранением основания, рисует текст текущим контекстом. WUnit больше не хранит Graphics/FontMetrics и не требует экранного устройства для получения кадра. GameField пропускает через один путь все Drawable, включая предметы, снаряды и попадания. ZBuffer стабильно сортирует по мировому baseY без ограничения слоя высотой окна; отсечение проверяет пересечение прямоугольников. |
| R03 | Единственный `UnitAnimations` на WUnit владеет движением, покоем, атакой и смертью. Общая `DeathAnimation` сохраняет исправления этапа 1. Повторная смерть не перезапускает анимацию; завершение вычисляется по времени, даже вне экрана. Движение отменяет визуальную атаку, возрождение сбрасывает состояние, смена набора во время движения и телепорт на ненулевые координаты безопасны. |
| R13, клиент | Удалены заменённые PlayerDeathAnimation/MonsterDeathAnimation, пустые DrawableItem/PickupAnimation и неработавший вызов pickup; удалён закомментированный дубликат WalkingDesu. Поиск активных ссылок перед удалением и после него выполнен. Предметные API common сохранены. |

Основание адаптаций и исторические SHA сохранены в
[реестре этапа 2](RECOVERY-STAGE-2.md#принятые-решения).
Исторические коммиты целиком не переносились.

### Поддержка состояний и fallback

| Набор | Движение / покой | Атака | Смерть |
| --- | --- | --- | --- |
| peasant | Свой набор, 8 направлений | Свой peasant_attack | peasant_death |
| peon | Свой набор, 8 направлений | Свой peon_attack вместо прежней подмены | Явный fallback peasant_death: собственного набора нет |
| poring | Существующие восточные/западные кадры для 8 направлений | Покой без отдельного аниматора атаки | poring_death |
| tower | Один существующий кадр для 8 направлений | Покой; событие BOLT и снаряд работают отдельно | Покой без аниматора смерти; завершение немедленное, действующий NPC не умирает |
| desu | Свой набор; EAST → SOUTH_EAST, WEST → SOUTH_WEST | Покой без отдельного аниматора атаки | Зафиксированный кадр покоя без аниматора смерти; завершение немедленное |

Fallback не создаёт отсутствующих наборов и не меняет тип юнита.
При статической атаке принятое событие остаётся доступным существующему пути
снаряда; дополнительной визуальной задержки нет. У peasant/peon граница
атаки — 750 мс, задержка появления снаряда — 375 мс без повторного прибавления.
Пути ресурсов и требования не расширились: `required-assets.txt` по-прежнему
содержит 280 путей, графика остаётся вне Git.

### Очистка и эффекты

Завершённые попадания и снаряды удаляются из очереди отрисовки, а мёртвые
монстры — также из коллекций мира после окончания анимации. Удаление игрока
больше не выходит до очистки players. Удалённый юнит освобождает визуальное
состояние, текст и выбранные объекты. Публичные методы очереди сохранены
для `SelfExecutor.getMethod`; `take()` устраняет гонку пропущенного notify,
повторное добавление Drawable выполняется атомарно. `GameField.close()`
останавливает собственные фоновые задачи и очередь, в том числе в проверках.

Снаряды получают мировой baseY; попадания сохраняют координаты и у последнего
кадра. Снаряд башни фиксирует точку назначения при запуске и не разыменовывает
текущий выбор цели во время paint. Завершённый снаряд больше не оставляет
последний кадр на экране. Это клиентская визуализация: серверный расчёт боя,
модель common и игровой протокол не менялись.

## Окружение и команды

Сборка: существующий контейнер `walking-desu_devcontainer-dev-1`,
Temurin JDK 21.0.13+9-LTS, Gradle Wrapper 9.8.2, локальные ресурсы
`.devcontainer/assets/client`. На хосте — Linux, DISPLAY=:0 через XWayland,
GUI OpenJDK 25.0.4.1 (Red Hat). Клиент и сервер скомпилированы для Java 21;
графический прогон на хосте использует Java 25.

В контейнере, из `/workspace`:

```sh
./gradlew build :client:publishDev
```

Команда прошла; `build` включает `:client:regressionCheck` и
`:server:networkSmoke`, упаковку модулей и дистрибутивов. Последний сетевой
прогон занял отдельный порт 38347 и завершился PASS. Проверка ресурсов прошла.
Сохраняется прежний unchecked cast при чтении сетевого пакета клиента;
предупреждение Float(double) исчезло с заменой старого кода текстового облака.

Графический прогон из корня на хосте после сборки (GUI Java, экран обязателен):

```sh
java -cp 'client/build/classes/java/checks:.devcontainer/artifacts/client/lib/*' \
  client.GraphicalClientCheck \
  server/build/libs/walking-desu-server-3.1.0-dev-standalone.jar
```

Итоговый графический прогон прошёл на отдельном порту 33651 с кодом выхода 0.
Драйвер сам запускает отдельную JVM сервера на порту 0 и два настоящих
WanderingGUI/ServerInteraction/GameField с отдельными сокетами и окнами в
одной проверочной JVM. Он проходит обычный диалог входа через EDT, отправляет
игровые команды и сохраняет снимки собственных окон. Это автоматизированный
GUI-прогон, пользовательского ручного прогона на этом этапе не было.
Работающий dev-сервер на 45000 не перезапускался, его JAR не заменялся.

Дополнительные юниты всех пяти типов и золото — явно локальные визуальные
фикстуры после сетевого сценария. Для просмотра эффектов на снимке удержаны
представительные кадры снаряда/попадания; их реальное время жизни независимо
проверено headless-тестом. Это не проверка серверного строительства, волн
или подбора фиктивного предмета.

## Ограничения и продолжение

- Прогон GUI автоматизирован; длительная ручная игра и полный цикл tower defence
  не повторялись. Локальные фикстуры не доказывают серверную работу этих механик.
- После остановки изолированного сервера старый ServerReaderTask может печатать
  EOFException и завершать клиент. Это прежний контракт завершения приложения,
  не ошибка отрисовки; драйвер завершает свой процесс, а не общий dev-сервер.
- Смерть peon использует явно описанный исторический fallback; новых изображений
  desu/tower для атаки/смерти не добавляли. Это сохранённые ограничения ресурсов.
- Предметная часть R13, операции инвентаря/сообщения и серверные контроллеры
  остаются этапам 4–5. Следующий этап — 4: предметы и сообщения по R04–R05.
