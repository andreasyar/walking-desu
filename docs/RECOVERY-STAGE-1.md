# Этап 1: проверка базы 3.1

Дата: 1 ноября 2026 года. Задача: [#4](https://github.com/andreasyar/walking-desu/issues/4),
эпик: [#2](https://github.com/andreasyar/walking-desu/issues/2).
Статус: пользователь повторил прогон графических клиентов и подтвердил
устранение первоначальных ошибок. Дополнительно исправлена анимация смерти
монстра после сообщения `Wow! 0`; это последнее изменение проверено
автоматически, повторный визуальный прогон именно этой правки ещё не проведён.
Этап завершён по результатам автоматических проверок и повторного
пользовательского прогона; завершение подтверждено пользователем.

Исходное состояние: `693505204087daae83dbecae32155e37a11ec9f2`,
ветка `codex/gradle-game-3.1`. Исправления, проверки и этот отчёт
сохранены вместе в коммите завершения этапа 1; точный SHA указан в issue #4.

## Окружение и команды

Сборка проверена в существующем dev container: Temurin JDK 21.0.13+9-LTS,
Gradle Wrapper 9.8.2, локальные изображения `.devcontainer/assets/client`.

Из `/workspace` в dev container:

```sh
./gradlew build
./gradlew :client:regressionCheck :server:networkSmoke
```

`build` собирает все модули, ZIP/TAR-дистрибутивы и standalone JAR сервера,
проверяет обязательные изображения и запускает обе проверки через `check`.
Проверки используют отдельный source set `checks`, без внешней тестовой библиотеки.
Обе команды завершились успешно. Сохраняются прежние предупреждения компилятора
клиента о `Float(double)` и unchecked cast в чтении сетевого пакета.

`networkSmoke` запускает отдельную JVM сервера с аргументом `0`:
ОС выбирает и сразу занимает свободный порт; проверки подключаются только
к нему. PID дочернего процесса принадлежит проверке, которая завершает его
в `finally`; вывод сохраняется во временный `walking-desu-smoke-*.log`.
Проверка не подключается к работающему серверу на 45000. Аргумент порта
доступен и при ручном запуске серверного JAR; без аргумента остаётся 45000.

Для публикации обновлённых артефактов остановить dev-сервер на хосте,
выполнить `./gradlew prepareDev` в контейнере, затем запустить сервер на хосте
по README. Во время этой проверки работающий dev-сервер не перезапускался,
его опубликованный JAR не заменялся.

## Найденные дефекты базы и исправления

1. **Деление на ноль при смерти игрока.** `doHit` обнулял здоровье до
   обработки `deathplayer`, а отрисовка уже обращалась к анимации с нулевым
   числом кадров. Смертельное попадание теперь запускает анимацию под общей
   блокировкой с отрисовкой. Повторное сообщение смерти не запускает её заново.
   Анимация инициализирована с создания, выбирает кадр без деления по модулю,
   удерживает последний кадр с правильными координатами. Проверены все восемь
   направлений, время до начала, границы кадров, окончание, возрождение и
   повторная смерть. Сетевой прогон проверяет смерть движущегося игрока.
2. **Золото не выбирается мышью.** Размеры предмета не задавались, а разные
   способы отрисовки использовали разные привязки. Клиент берёт размеры из
   настоящего изображения и использует центр предмета как мировую позицию.
   Проверены совпадение области клика со всеми пикселями спрайта и внешние
   границы. Shift берётся из самого события мыши; предмет под спрайтом игрока
   получает приоритет при подборе. Автоподбор использует общий радиус 50,
   отмена задачи видна рабочему потоку и не сбрасывается при старте.
3. **Собственный клиент жертвы не получал HIT.** Обнаружено сетевым прогоном:
   рассылка видящим цель не включает саму цель. Сервер дополнительно отправляет
   HIT жертве-игроку; проверяется доставка перед смертельным попаданием.
4. **EOFException при нормальном выходе.** EOF теперь завершает обработчик
   штатно без стека. Закрытие соединения гарантировано в `finally`, останавливает
   поток отправки и удаляет игрока из мира и видимости. Ошибка отправки тоже
   закрывает соединение. Оборванное подключение до handshake не завершает сервер.
   Сетевой прогон проверяет эти сценарии, `delplayer`, последующий вход и
   резкий обрыв TCP с удалением игрока. Очередь отправки не блокируется и
   позволяет разослать `delplayer` даже из прерванного потока отправки.

## Ограничения и завершение

В этой среде нет настроенного графического доступа dev container.
Регрессионные проверки клиента используют настоящие изображения в headless
режиме и не заменяют проверку Swing-окна. Случай «после падения игрок остаётся
на другом клиенте» отдельно не воспроизведён на исходной базе; исправлены
обнаруженные проблемы жизненного цикла соединения, а доставка `delplayer`
проверена сетевым прогоном. Пользователь повторил прогон двух обновлённых
клиентов и подтвердил устранение исходных ошибок.

Матрица и известные ограничения зафиксированы, блокирующие дефекты базы
исправлены, воспроизводимые проверки добавлены. Пользователь подтвердил
завершение этапа и поручил сохранить и опубликовать изменения и закрыть #4.
Последняя правка анимации монстра проверена автоматически; отсутствие её
отдельного визуального прогона сохранено как ограничение доказательств.
Следующий этап — отбор изменений третьего поколения (этап 2).
Новые исторические изменения в рамках этапа 1 не переносились.


## Повторный пользовательский прогон и `Wow! 0`

После обновления клиентских и серверных артефактов пользователь подтвердил,
что ранее описанные ошибки устранены, а остальной прогон вопросов не вызвал.
Это подтверждает исходные исправления, для которых выше в матрице был указан
повторный визуальный прогон. Отдельных количественных замеров инвентаря и
пошагового протокола пользователь не предоставлял.

Единственное новое наблюдение — сообщение `Wow! 0` после смерти монстра.
Источник: `MonsterDeathAnimation.getSprite`. Как и у игрока, смертельный HIT
мог обнулить здоровье раньше запуска анимации по `deathmonster`. Сообщение
означало нулевую длительность анимации; защитная ветка затем пыталась получить
кадр с индексом `-1`, поэтому считать её безвредным отладочным выводом нельзя.

Исправление: анимация монстра инициализирована при создании, смертельный HIT
сразу запускает её и останавливает движение под общей блокировкой с отрисовкой.
Повторное `deathmonster` не сбрасывает анимацию. Выбор и привязка кадров,
включая последний, исправлены аналогично игроку. Добавлены проверки всех
восьми направлений, каждого кадра, окончания, смертельного HIT до прихода
`deathmonster` и повторного сообщения смерти. `./gradlew build :client:publishDev`
завершился успешно; обновлённый клиент опубликован локально. Серверного
изменения для устранения `Wow! 0` не требуется.
