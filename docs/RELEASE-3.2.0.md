# Выпуск Walking Desu 3.2.0

Дата: 1 ноября 2026 года. Задача: [#9](https://github.com/andreasyar/walking-desu/issues/9).
Исходники выпуска: тег `v3.2.0`. После этапа 14 основная ветка содержит 4.2;
поддержка стабильной 3.2 — ветка `codex/game-3.x` (снимок `master` на момент
сохранения третьей линии) и этот релиз.

## Комплект и запуск

В [GitHub Release](https://github.com/andreasyar/walking-desu/releases/tag/v3.2.0)
публикуются клиентский и серверный ZIP/TAR, standalone JAR сервера и
`SHA256SUMS`. Клиентский архив не содержит изображений. Перед запуском
скопируйте свой локальный `img/` в `walking-desu-client-3.2.0/assets/`;
[подробности и структура каталогов](CLIENT-ASSETS.md). Общая библиотека включена в дистрибутивы;
для standalone JAR сервера отдельный common JAR не нужен.

Проверить скачанные файлы из одного каталога:

```sh
sha256sum -c SHA256SUMS
unzip walking-desu-client-3.2.0.zip
unzip walking-desu-server-3.2.0.zip
walking-desu-server-3.2.0/bin/walking-desu-server 45001
# В другом терминале графического сеанса:
walking-desu-client-3.2.0/bin/walking-desu-client localhost 45001
```

В Windows распакуйте ZIP и используйте `.bat` из `bin/`.
Java 21 или новее обязательна для обоих компонентов; клиент требует GUI Java
и доступного графического сеанса. Хост и порт передаются клиенту явно.
Сервер также запускается командой
`java -jar walking-desu-server-3.2.0-standalone.jar 45001`.
Порт `0` выбирает ОС, без аргумента используется `45000`.

Ник содержит 3–10 символов, без кавычек и переводов строк. Для двух игроков
запустите два клиента с разными никами. Движение — клик по карте; выбор цели — Shift+клик, атака — F3,
постройка башни у игрока — F4. Подбор золота — F5 или Shift+клик.
Текст отправляется кнопкой Send; перед игровыми клавишами верните фокус
кликом по карте.

## Исправление упаковки и сборка из тега

Первоначальные клиентские архивы включали изображения. 1 ноября 2026 года
они удалены и заменены архивами без графики. Публичный архив доказательств
также заменён текстовыми логами без PNG. Серверные архивы не изменены.
Тег `v3.2.0` сохранён: поправка касается упаковки и внешних ресурсов,
игровые Java-классы остаются прежними.

Рядом с архивами опубликована `client-external-assets.patch`. Она фиксирует
изменения сборки после исходного тега и позволяет воспроизвести исправленную
упаковку. Не используйте первоначальный тег без этой поправки для публикации
клиентских архивов.

В чистом checkout с JDK 21:

```sh
git checkout --detach v3.2.0
git apply /absolute/path/to/client-external-assets.patch
./gradlew clean build -PclientAssetsDir=/absolute/path/to/client-assets
```

Каталог ресурсов должен содержать `img/` и все пути из
`client/required-assets.txt`. Wrapper проверяет SHA-256 Gradle 9.8.2.
Сборка включает inventoryCheck, regressionCheck, combatCheck,
itemNetworkCheck и networkSmoke. Для неё нужны локальные TCP-соединения.
Сервер и клиентские архивы собираются без графических ресурсов:
`./gradlew assemble`. Визуальные проверки `build` требуют локальные изображения.

Архивы: `client/build/distributions/walking-desu-client-3.2.0.zip`/`.tar`,
`server/build/distributions/walking-desu-server-3.2.0.zip`/`.tar`;
самостоятельный сервер — `server/build/libs/walking-desu-server-3.2.0-standalone.jar`.
Файлы архивов создаются с фиксированным порядком и временными метками.
Изображения не влияют на содержимое публичных JAR/ZIP/TAR.
Происхождение и неоднозначности набора описаны в README и аудите ресурсов;
локальные листы peon воспроизводятся по `docs/PEON-SPRITES.md`.

## Обновление и возврат

Протокол предметов изменён относительно исторической 3.1. Клиент и сервер
обновляются вместе, из одного выпуска. Перед заменой остановите клиентов и
сервер; для терминального сервера используйте Ctrl+C, для Compose — `stop server`.
После замены запускайте сервер, затем клиенты. Работающая JVM не перечитывает
заменённый JAR.

Перед обновлением сохраните предыдущий комплект клиента и сервера целиком
в отдельном каталоге вместе с ресурсами, настройками запуска и контрольными
суммами. Для возврата остановите новую пару и запустите сохранённую старую пару
на прежнем порту. Не смешивайте библиотеки из разных каталогов.

Предыдущая проверенная база этапа 5: `bd9d0ba429edea66ed5f59d2cbd38719623d19b2`
(игровой код `29d15ed09e9021caa0ab76e34153c937218a3590`). При отсутствии
сохранённых архивов соберите этот коммит в отдельном checkout с JDK 21 и
тем же внешним каталогом изображений; версия его артефактов — `3.1.0-dev`.
Возврат не требует переписывания `master` или перемещения тегов.

## Ограничения

- Это восстановленный прототип. Подтверждены сценарии отчёта этапа 6;
  длительная нагрузка и работа через публичный интернет не проверялись.
- GUI-проверки автоматизированы на Linux с OpenJDK 25/XWayland; сборка и
  серверные проверки выполняются на JDK 21. Windows/macOS не прогонялись.
- При малом размере окна часть элементов управления обрезается; остаются
  исторические привязки интерфейса и крупное зелёное облако текста.
- Полный цикл усиления/100 пропусков/сброса проверяется детерминированно на
  контроллерах. В GUI проверена естественная первая волна.
- При остановке изолированного сервера клиентский reader может вывести
  EOFException после успешного сценария. Это известная диагностика клиента;
  серверный EOF/reset и повторный вход проверяются отдельно.
- Точное соответствие историческим пикселям двух исходных изображений
  (`map.png`, `peasant_walk/w_01.png`) не доказано; ресурсы вне Git.
- Исторические 4.0/4.1 — незавершённая отдельная линия. Их теги и архив
  `codex/history/4.x-original` сохранены и не обозначают готовую замену 3.2.
