# Внешние ресурсы wand6

Клиентский JAR и публичные ZIP/TAR не содержат изображений. Для wand6
нужны файлы из `client/required-assets.txt`: атлас `img/summer.png` и
кадры персонажа:

- `img/peasant_walk/`: четыре кадра на каждое из восьми направлений;
- `img/peasant_stand/`: один кадр на направление;
- `img/peasant_attack/`: пять кадров на направление;
- `img/peasant_bolt/`: один кадр на направление;
- `img/peasant_death/`: три кадра на каждое из ne, nw, sw, se.

Всего 100 кадров и один атлас. Направления: e, ne, n, nw, w, sw, s, se;
имена — `<направление>_01.png` … `_05.png` в зависимости от состояния.
Поместите их с теми же путями внутри `assets/` распакованного
`wand6-client-4.2.0-dev`, рядом с `assets/required-assets.txt`.
Кадры берутся из того же внешнего набора, что использует 3.2. Walk/stand
вырезаются как (8,8,56,56) из изображений минимум 64×64. Attack/death/bolt
используются целиком, как в 3.2. Для смерти повторено соответствие 3.2:
e/ne/n → ne, nw/w → nw, sw/s → sw, se → se. Атака — 150 мс на кадр,
смерть — 150 мс на кадр. Собственного peasant_hit в наборе нет: попадание
показывается красным импульсом и числом серверного урона.
Все перечисленные кадры обязательны: отсутствующий/повреждённый ресурс
даёт ошибку с путём до подключения к серверу, без графической заглушки.

Запускайте `bin/wand6-client localhost <port>` (Windows: `.bat`). Скрипт
добавляет `assets/` в classpath независимо от рабочего каталога. Для прямого
запуска: `java -cp 'lib/*:assets' wand6.client.Wand localhost <port>`;
в Windows разделитель `;`. Без читаемого атласа клиент завершается с понятной
ошибкой до подключения к серверу. Минимальные размеры — 512×672: исторический
renderer вырезает клетки 32×32 вплоть до прямоугольника (448,640,32,32).

## Локальный кандидат

Для этапа 7 использован существующий локальный файл
`recovered/orphan-branch-sprite-review/images/local-img/tiles/summer.png`
размером 512×768. Его копируют в отдельный набор
`.devcontainer/assets/wand6/img/summer.png`. SHA-256 и результаты проверки
приведены в `docs/RECOVERY-STAGE-7.md`.

Это технически пригодный кандидат из локального архива. Точное соответствие
оригинальному историческому атласу и происхождение прав не установлены.
Сборка не скачивает и не публикует этот файл; пользователь предоставляет
свой локальный ресурс. На этапе 8 проверены отрисовка атласа, глобальные соседние клетки на
стыках фрагментов и переход в настоящем окне; это не подтверждает
историческую точность рисунка и происхождение прав.

## Разработка

`./gradlew assemble` собирает дистрибутивы без ресурсов.
`./gradlew :client:verifyClientAssets` проверяет наличие локального набора;
другой каталог задаётся через `-PclientAssetsDir=/absolute/path/to/assets`.
`./gradlew :client:run --args='localhost <port>'` добавляет этот каталог
в classpath. `:client:publishDev` подготавливает только отдельный локальный
клиент `.devcontainer/artifacts/wand6-client/`, включая внешний `assets/img/`.
Он не заменяет клиент или сервер 3.x. Публичные архивы проверяются задачей
`:client:verifyClientPackaging`. Изображения и PNG проверок остаются вне Git.

Каменный тайл (256,288,32,32) обозначает непроходимые высоты ≥200;
вода ≤50 также непроходима. Сетка выключена по умолчанию и включается
`-Dwand6.debugMap=true`. Локальные кадры peasant скопированы из
`.devcontainer/assets/client/img/peasant_walk/` и `peasant_stand/` в аналогичные
подкаталоги `.devcontainer/assets/wand6/img/`. Это внешние входы, не новые
созданные изображения; права и ограничения исходного набора сохраняются.

Боевые кадры этапа 10 скопированы из локальных
`.devcontainer/assets/client/img/peasant_attack/`, `peasant_death/` и
`peasant_bolt/` в такие же подкаталоги wand6. Это существующие внешние
изображения 3.2; сборка их не скачивает, права исходного набора сохраняются.
